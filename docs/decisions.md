| 74 | 官网首页 | `/` 是独立的静态官网（`web/public/landing.html`），不经 Vue。第一次来的人先看「这是什么」，而不是先面对输入框；文件缺失时回退重定向到 `/logshare/` |
| 75 | 追问可恢复 | `ask_user` 走三级通道：`status` 帧 `type=ask` → `done.asks` → 消息 `meta.asks` 落库。「已回答」由其后是否出现用户消息判定，不设额外状态字段 |
| 76 | 品牌标记 | 顶栏与官网不使用方块「LR」标记，只保留文字品牌。方形字标容易被读成占位符，且与「勘验卷宗」的字级层级冲突 |
| 77 | 垂直对齐的度量方式 | 输入区只用一个 `--row: 40px` 推导所有居中：提示符固定在首行、按钮贴末行。**禁止**用 `padding-bottom` 的魔法数字凑对齐——实测那样会差 1.8–2.8px，且随字号变动而失效 |
| 78 | 图标按钮必须是正方形 | `.btn--icon` 的宽度曾固定 32px 而 `--sm` 高度 26px，得到 26×32 的长方形，图标看着偏下、右边比别的元素宽。现在宽度跟随高度 |
| 79 | 官网移动端网格 | 必须写 `minmax(0, 1fr)` 而非 `1fr`：`1fr` 的最小值是 min-content，日志示例里的不换行长行会把整列撑到 540px+，390px 屏幕上直接横向溢出 |
| 80 | 响应压缩 | 自写而非引中间件（`src/server/compress.ts`）：只有两个写出点，中间件要额外处理与 SSE 的冲突。**SSE 绝不压缩**（压了就没有流式），<1KB 不压，br 优先于 gzip。实测 265KB 日志 → 35.7KB（-86%） |

## 关键纠正的根因（一句话版）

- D11：正文模板迫使模型填表 → 简单问题被撑长、无关环节被硬编
- D18：纯 IP 限额在 CGNAT（移动端主流）下误伤真实整出口用户
- D20/24：方法论进 RAG 会被当事实检索出来，且稀释 BM25
- D25：按启动器组织是 `O(启动器×问题)` 无限增长；正确是 `O(MC问题空间)+O(日志格式)`
- D29：领域知识会**原文注入全局提示词**，可匿名写入即等于「任何人都能改写所有用户的结论」
- D32：旧评分器的证据分是**工具调用次数的阶跃函数** → 实测「0 工具 + 结论完整」253 条 overall 全部恰好 68，
  与答案质量无关，长期无人发现是因为记录存在 600MB 单文件里、没人问得起
- D34：生产看板 `totalAnalyses` 曾长期恒等于 100，因为聚合走了带 100 上限的分页接口，
  且**没有任何报错**——统计口径的静默退化比不统计更危险
